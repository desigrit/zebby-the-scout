# Zebby 2.1.0

## Credits without signup

- Buy and use credits with a guest wallet. No Zebby email code, signup, or sign-in screen.
- Save a private recovery code from Settings or after your first purchase, and restore credits on a new installation.
- Pair another Windows or Mac computer using a code that expires after ten minutes. Both computers share one balance.
- View connected computers and disconnect one with confirmation. Your credits remain in the wallet.
- Replace a recovery code with confirmation. Existing connected computers keep access.

## Keeping access safe

Device credentials stay encrypted in the app's local profile, outside the applications database. A lost connection reply or failed settings save retains enough information to finish connecting after a restart. Authentication failures preserve saved access and cached balances. Settings writes now commit as complete files, and app logs redact wallet tokens and recovery codes.

Existing valid paid sessions retain their wallet identity and balance when converted to guest access. There is no application database migration in this release.

## For the owner

The [updated setup guide](https://github.com/desigrit/zebby-the-scout/blob/main/credits-service/README.md) covers Supabase PostgreSQL, Stripe test mode, hosting, provider keys, and the public desktop service URL. Supabase email sign-in, email templates, and an SMTP sender are no longer required. If you ran the earlier ledger schema, rerun the updated schema before deploying this service.

Checkout remains disabled until the owner configures the hosted service. No live payment has been taken during implementation verification. Local models, Ollama, and personal API keys remain available.
